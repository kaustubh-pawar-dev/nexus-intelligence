# NEXUS Intelligence

**Enterprise Decision Intelligence & Predictive Analytics Platform** - an end-to-end data analytics project built on a fully **synthetic** enterprise dataset.

> **Data notice:** all data in this repository is synthetic and generated by the code in `src/nexus/datagen`. Any figures, patterns or results are simulated and say nothing about real companies or customers.

> **Status:** work in progress. The data engineering, SQL analytics and statistical analysis layers are implemented. Predictive modelling, dashboard and scenario features are planned (see [Roadmap](#roadmap)).

## Business problem

Real enterprise data arrives messy and spread across operational systems, and decisions built on it are only as good as the cleaning and analysis behind them. NEXUS simulates a company (suppliers, products, customers, orders, payments, refunds, purchase orders, inventory, shipments) and builds the full analytics workflow on top of it: generate data, inject realistic defects, clean and validate it, analyse it with SQL and statistics, and keep every step reproducible and tested.

## Implemented features

- **Synthetic data generation** (seeded, reproducible): 11 tables including 24 suppliers, 120 products, 5,000 customers, orders and order lines, payments and refunds, purchase orders, daily inventory, shipments, and daily business metrics (2023-01-01 to 2025-12-31).
- **Injected data-quality defects**: an "as delivered" copy of four tables with known, recorded defects, so cleaning can be measured against ground truth.
- **Layered PostgreSQL warehouse**: `raw` (as delivered, loaded as text) -> `staging` (typed, deduplicated, row-level issue log) -> `analytics` (constraint-checked), plus a `core` schema loaded from the clean files for reconciliation.
- **Cleaning pipeline** with every row-level decision logged (fixed, flagged, dropped, quarantined).
- **SQL analytics** (11 queries in `sql/analytics`): monthly revenue, category and segment contribution, product ranking, cohort retention, customer LTV, RFM segments, supplier performance, inventory turnover and revenue leakage.
- **Statistical analysis**: data profiling and seven hypothesis tests reporting effect sizes and Holm-adjusted p-values, separating statistical from practical significance.
- **Multivariate analysis**: regression models and confounding checks (associations, not causal claims).
- **Automated tests**: 232 pytest tests.

## Technology stack

Python 3.10+, PostgreSQL, SQL, pandas, NumPy, SciPy, statsmodels, SQLAlchemy, psycopg 3, python-dotenv, pytest.

## Architecture

```
generators (seeded) -> data/raw (clean CSVs, ground truth)
                    -> data/raw/dirty (injected defects)
                              |
                         schema raw -> schema staging -> schema analytics
                                                                  |
                                          SQL analytics, statistics, multivariate models
```

## Project structure

```
src/nexus/    library code (config, db, datagen, cleaning, promotion, stats, multivariate)
scripts/      runnable entry points (generate, load, build, analyse, summarize)
sql/          schema.sql and analytics queries
tests/        pytest suite
docs/         data_dictionary.md (tables, defects, layers, metric definitions)
data/, logs/  generated locally, not committed
```
## Setup (Windows, PowerShell)

Requires Python 3.10+ and a local PostgreSQL server.

```powershell
git clone https://github.com/KaustubhP234/nexus-intelligence.git
cd nexus-intelligence
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
pip install -e .
Copy-Item .env.example .env
```

Edit `.env` and set `NEXUS_DB_PASSWORD` (never commit `.env`).

Create the database and role once (example; adjust to your PostgreSQL setup and use your own password):

```powershell
psql -U postgres -c "CREATE ROLE nexus_app LOGIN PASSWORD 'your-password-here';"
psql -U postgres -c "CREATE DATABASE nexus_intelligence OWNER nexus_app;"
```

## Running the pipeline

```powershell
python scripts/check_environment.py

# 1. Generate synthetic data into data/raw (default seed 42, set in .env)
python scripts/generate_reference_data.py
python scripts/generate_customer_data.py
python scripts/generate_order_data.py
python scripts/generate_payment_data.py
python scripts/generate_purchase_order_data.py
python scripts/generate_inventory_data.py
python scripts/generate_shipment_data.py
python scripts/generate_daily_metrics_data.py
python scripts/generate_dirty_data.py

# 2. Build the database layers
python scripts/init_database.py
python scripts/load_core.py
python scripts/load_raw.py
python scripts/build_staging.py
python scripts/build_analytics.py

# 3. Analyse
python scripts/run_sql_analytics.py
python scripts/run_sql_analytics_2.py
python scripts/run_stats.py
python scripts/run_multivariate.py
```

`scripts/summarize_*.py` print summaries and checks for each stage. See `docs/data_dictionary.md` for table definitions, defect types and metric definitions.

## Testing

```powershell
python -m pytest -q
```

## Configuration

Settings are read from environment variables (`.env`, see `.env.example`): `NEXUS_ENV`, `NEXUS_LOG_LEVEL`, `NEXUS_RANDOM_SEED`, and `NEXUS_DB_HOST`, `NEXUS_DB_PORT`, `NEXUS_DB_NAME`, `NEXUS_DB_USER`, `NEXUS_DB_PASSWORD`. No secrets are stored in the code.
